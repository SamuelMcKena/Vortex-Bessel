# Publication_Study coverage audit

This page records what was carried forward from the original Publication_Study workspace and what was deliberately left as historical provenance.

The goal is **functional coverage without duplicate competing implementations**: previous scientific workflows remain reachable, but dated copies/backups are not allowed to masquerade as equally current code.

## Original numbered publication notebooks

All eleven original numbered workflow roles are represented by current topic-organised notebooks. See `docs/PUBLICATION_STUDY_MAP.md` for the exact old-name → current-path mapping.

The current layout separates:

- scalar beam diagnostics / robustness / sweeps / validation;
- lab-realistic SLM / 4F / physical-axicon / sample-interface routing;
- vector/Jones-field studies;
- materials/application calculations;
- advanced capsule, hexagonal/polygonal and N-fold studies;
- later digital-twin work;
- measured experimental axicon-aberration correction.

The normal entry point is now discovery-based rather than a hard-coded historical notebook list:

```powershell
vortex-bessel --list
vortex-bessel --stage all
```

## Original `NB_*` notebooks

The original holographic axicon, physical axicon, axicon comparison, through-sample, full-journey, validation, materials and hexagon `NB_*` workflows have current replacements under `notebooks/lab_realism/`, `notebooks/scalar/`, `notebooks/materials/`, `notebooks/advanced/`, `notebooks/vector/` and `notebooks/digital_twin/`.

## Original checkpoint scripts

The old workspace also contained one-off checkpoint runners for hollow/hexagonal/polygonal/Zernike/polarised-train studies. They are **not promoted as parallel canonical engines** in the clean repository.

Their maintained scientific building blocks remain in the current modules such as:

- `vbb_hex_outline.py`
- `vbb_polygonal.py`
- `vbb_discrete.py`
- `vbb_polarized_train.py`
- `vbb_hexagon_study.py`
- `vbb_hexagon_metrics.py`

and their current interactive study routes are under `notebooks/advanced/`, `notebooks/vector/` and `notebooks/digital_twin/`.

Specialist current error/axicon runners are retained under `tools/`; see `docs/CURRENT_CODE_INDEX.md` and `docs/TOOLS_GUIDE.md`.

If an exact historical checkpoint output must be reproduced for provenance, use the old repository/commit as the source record. If that calculation becomes active research again, migrate its scenario into the current package/tests rather than restoring a second stale engine.

## Generated outputs

The original workspace contained a large generated `outputs/` tree. The clean repository intentionally carries the governed machine-readable validation/evidence subset under `outputs/validation/` rather than every historical render, scratch array and superseded figure.

New outputs should be regenerated by current code. Notebook execution goes beneath `outputs/executed_notebooks/` without overwriting source notebooks.

## Deliberately excluded duplicate/history material

The following classes of files are not current code and were intentionally not carried forward as competing implementations:

- `vbb_study - Copy/`;
- dated `backups/`;
- `__pycache__/` and `.pyc` files;
- `run_* - Copy.py` duplicates;
- bulk historical/superseded generated-output trees;
- temporary/cache execution products.

The old repository remains the provenance archive for these files.

## New work added beyond Publication_Study

The clean repository also carries the later Phase 2K-audited numerical architecture and the current measured q=20 axicon-aberration workflow under:

`notebooks/experimental/axicon_aberration_correction/`

That means the new repository is a superset of the original Publication_Study **at the maintained scientific-workflow level**, while deliberately not being a byte-for-byte copy of every backup and generated artifact.
