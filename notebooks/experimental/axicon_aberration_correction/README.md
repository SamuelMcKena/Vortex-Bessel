# Axicon vortex–Bessel z-scan correction

This directory contains the experimental BeamGage z-scan analysis, global multi-plane
wavefront reconstruction, constrained q=20 modal diagnostics, inverse-error
falsification, SLM-preview tooling, high-resolution propagation/profile figures,
and measured beam-axis diagnostics.

## Main entry point

The canonical notebook is now:

`Bessel_zscan_physics_consistent.ipynb`

It replaces the old inline phase-retrieval/correction preview in
`Bessel_zscan_alignment_correction.ipynb`.

The old notebook contained two important interpretation/physics problems:

1. its plot titled **Recovered phase at z0** displayed the *total* wrapped phase.
   For q=20 this naturally contains a strong 20-fold wrapped vortex structure, so
   that image must not be interpreted as an aberration map;
2. the reconstructed field was returned at the first measured plane, but the old
   longitudinal preview then propagated that field using the absolute relative-z
   labels (-17 ... 0 mm) instead of distances from the reconstruction plane.  That
   double-counted the propagation reference and made the old before/after XZ/YZ
   preview non-physical.

The new workflow enforces one complex reference-plane field for the whole z stack.
Every measured/model plane is generated from that one field with the same
band-limited angular-spectrum propagator.  The longitudinal information therefore
constrains the recovered phase through propagation; there is no independently
adjustable phase at every z.

Set the data directory before starting Jupyter when the raw acquisition is stored
elsewhere:

```powershell
$env:BESSEL_ZSCAN_DATA_DIR = 'D:\path\to\z-scan 2 1010'
jupyter lab
```

or run the analysis directly:

```powershell
python global_multiplane_retrieval.py --data-dir 'D:\path\to\z-scan 2 1010'
```

Install the dependencies with:

```powershell
python -m pip install -r requirements.txt
```

## What “phase” means in the current workflow

A phase correction is a **2-D phase function at one physical plane**.  Its
three-dimensional consequences are generated by wave propagation.  The code does
not fit an independent `phi(x,y,z)` and then pretend that can be sent to an SLM.

The current solver separates:

- **total reconstructed phase** — contains the q=20 topology and nominal propagation;
- **complete nominal phase** — the q=20 conical/propagated reference field;
- **residual phase** — `angle(U_retrieved * conj(U_nominal))` on a confidence mask;
- **camera-plane conjugate** — a virtual diagnostic only, not an SLM2 command.

Subtracting only `20*theta` is insufficient for a propagated Bessel field because
radial Bessel sign changes, conical/radial phase and ordinary propagation phase
also belong to the nominal solution.

## Analysis modules

- `physics_consistent_multiplane.py`: common BL-ASM propagation, global multi-plane
  alternating-projection retrieval, complete-nominal residual phase, fixed-coordinate
  longitudinal sections and virtual camera-plane phase screens.
- `global_multiplane_retrieval.py`: canonical measured q=20 driver with ideal-only
  absolute-z registration, interleaved held-out planes, residual-phase decomposition,
  error recreation and longitudinal diagnostics.
- `modal_vortex_bessel.py`: BeamGage loading and constrained vortex–Bessel modal fitting.
  This is a secondary annular diagnostic, not the primary 3-D phase retrieval.
- `q20_modal_analysis.py`: independent per-plane q=20 modal fits.  Useful for angular
  defect spectra and falsification, but independent per-plane fits do not constitute
  one propagated wavefield.
- `phase_error_recreation.py`: legacy per-plane modal closure diagnostic.  The global
  multi-plane recreation and `single_mask_inverse_forward_test.py` are stronger tests.
- `single_mask_inverse_forward_test.py`: one-input-mask, one-common-propagator
  falsification test for a proposed input-plane phase map.
- `comprehensive_error_validation.py`: high-resolution profiles/metrics.  Any
  “corrected per-plane model” in that module is a stack of independent modal
  counterfactuals, not a propagated corrected 3-D beam.
- `measured_beam_path_trajectory.py`: absolute full-sensor beam-centre trajectory,
  kept separate from morphology-centred phase retrieval.
- `slm2_complete_mask_preview.py`: native 1920×1080 SLM2 previews.  These remain
  hardware-blocked until coordinate and LUT calibration exists.
- `iterative_correction_controller.py`: held-out-plane proposal controller; experimental
  acceptance still requires a new camera z stack.

## Validation logic

The canonical reconstruction deliberately holds out interleaved z planes.  A useful
retrieved field must predict those planes without being refitted there.

A stronger causal check applies the retrieved residual phase to the **nominal**
reference field and propagates that one field through all z.  The residual phase is
not accepted as the physical cause of the measured morphology unless this
phase-error recreation improves held-out agreement over the nominal model.

The tests in `tests/test_physics_consistent_multiplane.py` lock the key invariants:

- propagation distances are `z_j - z_ref`;
- total q/topological phase is removed by comparison with the complete nominal field;
- every z plane comes from one common reference field;
- physical longitudinal sections preserve real transverse drift rather than
  silently re-centring each plane.

## Scalar versus vector propagation

The measured free-space camera z-scan is treated with the scalar angular-spectrum
model.  A separate vector/high-NA propagation model is required when longitudinal
field components such as `E_z` become non-negligible near a high-NA focus.  That is
a different physical question from the z-dependent phase mistake fixed here and
must not be approximated by adding an arbitrary “longitudinal correction phase”.

## Hardware boundary

No camera-plane phase map in this workflow is hardware-ready.  Before a residual can
be transferred to SLM2, the following are still required:

- camera ↔ SLM optical transform / relay magnification;
- x/y parity and rotation;
- illuminated SLM footprint and beam centre;
- 1030-nm phase response / gray-level LUT;
- a physically defined back-propagation/mapping from the reconstruction plane to
  the SLM plane.

After that mapping is measured, the proposed conjugate phase must be applied on the
real system and accepted only if a **new post-correction z-scan** improves the
pre-declared experimental metrics.  Until then `hardware_ready = False`.
